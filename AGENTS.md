# Руководство для контрибьютеров

Этот документ содержит практическую информацию для разработчиков, желающих внести вклад в проект.

## Структура проекта и организация модулей

Проект `kursach` представляет собой веб-приложение на TypeScript с использованием Vite в качестве сборщика.

**Основная структура:**
```
/
├── src/                      # Исходный код приложения
│   ├── main.ts              # Точка входа приложения
│   ├── style.css            # Основные стили
│   ├── components/          # React компоненты
│   └── state/               # State management система (ООП)
│       ├── CounterState.ts  # Состояние счетчика
│       ├── TodoState.ts     # Состояние списка задач
│       └── Store.ts         # Основной store
├── public/                  # Статические ресурсы
│   └── vite.svg             # Логотип Vite
├── package.json             # Конфигурация зависимостей
├── tsconfig.json           # Конфигурация TypeScript
└── index.html              # Основной HTML файл
```

## Команды сборки, тестирования и разработки

**Для локальной разработки:**
```bash
npm run dev        # Запуск dev-сервера с горячей перезагрузкой
```

**Для сборки проекта:**
```bash
npm run build     # Сборка проекта для production (tsc && vite build)
npm run preview   # Предпросмотр собранного проекта
```

**Установка зависимостей:**
```bash
npm install       # Установка всех зависимостей
```

**Описание команд:**
- `npm run dev` - запускает локальный сервер разработки Vite на порту 5173 с горячей перезагрузкой
- `npm run build` - компилирует TypeScript код и создает production сборку
- `npm run preview` - локально развертывает production сборку для тестирования

## Стиль кода и правила именования

**TypeScript правила:**
- Используйте строгий режим TypeScript (`strict: true`)
- Всегда указывайте типы для параметров функций и возвращаемых значений
- Используйте интерфейсы вместо type aliases для описания объектов
- Придерживайтесь camelCase для переменных и функций
- Используйте PascalCase для классов и интерфейсов

**Структура кода:**
- Исходный код располагается в директории `src/`
- Каждый файл должен содержать только один основной экспорт
- Компоненты располагаются в `src/components/`
- State management логика в `src/state/`

**Тестирование:**
- Все новые функции должны сопровождаться тестами
- Имена тестовых файлов должны заканчиваться на `.test.ts` или `.spec.ts`
- Тесты должны быть самодокументируемыми с использованием describe/it блоков

## Рекомендации по VCS: коммиты и пулл реквесты

**Конвенции коммитов:**
Используйте соглашение Conventional Commits:
- `feat:` - новая функциональность
- `fix:` - исправление ошибки
- `docs:` - изменения в документации
- `style:` - форматирование, отсутствующие точки с запятой и т.д.
- `refactor:` - рефакторинг кода
- `test:` - добавление тестов
- `chore:` - обновление сборки, конфигурации

Примеры:
```
feat: добавить state management систему
fix: исправить обработку событий в CounterState
docs: обновить AGENTS.md с новыми командами
```

**Требования к пулл реквестам:**
1. Каждый PR должен содержать ясное описание изменений
2. Связанные issue должны быть упомянуты с помощью `#номер_issue`
3. Код должен проходить линтинг и компиляцию без ошибок
4. Изменения должны быть самодостаточными и атомарными
5. Добавьте скриншоты для изменений UI, если это применимо

## Архитектура проекта

Проект использует собственную реализацию State Management системы на основе ООП:
- **Action** - базовый класс для действий
- **Reducer** - абстрактный класс для обработки действий
- **Store** - централизованное хранилище состояния

Принципы архитектуры:
- Разделение ответственности между компонентами
- Иммутабельность состояния
- Однонаправленный поток данных
- Dependency injection через конструкторы

## Настройка среды разработки

**Требования:**
- Node.js версии 18 или выше
- npm или yarn для управления зависимостями

**Быстрый старт:**
```bash
git clone <репозиторий>
cd kursach
npm install
npm run dev
```

**Рекомендуемые инструменты:**
- VS Code с расширениями для TypeScript
- ESLint для линтинга
